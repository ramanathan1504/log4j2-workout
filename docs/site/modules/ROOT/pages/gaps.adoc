= Open gaps

Everything not done, and what closing it would take. The complete list — nothing
is recorded only elsewhere.

== Coverage

`log4j-plugin-processor` unreachable on 3.x::
The one shippable 3.x module the bench does not reach (21 of 22). `@Plugin` moved
package between the lines, so plugin sources cannot compile against both without
two source sets. A fact about writing Log4j plugins, not a bench defect — any
third-party plugin targeting both lines faces it.

`jakarta-web` and `javax-web` skip in sweeps:: *CLOSED.*
Both used to serve until interrupted, so no cell could finish one. Each launcher
now has a `selfTest()` that drives its own endpoints over real HTTP and exits
with a status, and `INTERACTIVE_APPS` is empty — both sweep to `PASS`.

No full `--all` sweep recorded::
~37,000 cells; about six hours with `--scenario`, roughly a week without. Run to
~700 cells and stopped deliberately. A broad matrix is a tripwire, not a
microscope — every finding came from a targeted run. Worth doing once as a
baseline to diff a specific Log4j candidate against.

== Samples

Seven modules built and green against `logging-log4j-samples`; eight proposed and
not built. Three are feasible and simply unwritten (`migration-1x`,
`garbage-free`, `web`); three are blocked on dependencies that project's parent
does not manage (`jdbc-appender`, `smtp`, `network-appenders`).

Nothing has been offered upstream. Each module is verified by copying into a
scratch checkout of the clone, building, and reverting it.

== Environment

Cassandra 5 unreachable::
`log4j-cassandra` ships DataStax driver 3.11, which negotiates protocol v4 at
most. Against 5.0 the connection neither completed nor errored. Cassandra *4.1*
works and is what the compose file pins. Closing it upstream means rebuilding
`log4j-cassandra` against driver 4.x.

Documentation site has no URL::
`docs/site/index.html` is self-contained and opens in any browser; publishing
failed with `init 404`, a service problem rather than a content one.

== What is not a gap

Stated because each looks like one:

* *Ten of nineteen apps cannot run on 3.x* — their Log4j modules were never
  published for it. Upstream reality.
* *`SerializedLayout` is not exercised* — deprecated, and refuses to build
  without `log4j2.enableSerialization`.
* *`${jndi:}` renders unresolved* — deliberate. The bench never sets
  `log4j2.enableJndiLookup`.
* *`appender-composite` emits three errors every run* — deliberate. `Failover`
  cannot be demonstrated without a primary that fails.
