= Issues raised

Defects found with this bench and reported to
https://github.com/apache/logging-log4j2[apache/logging-log4j2].

The common thread is that every one is *silent in production*. Log4j catches
appender exceptions, reports them through the `StatusLogger`, and lets the JVM
exit 0 — so none of these announces itself.

== Filed

https://github.com/apache/logging-log4j2/issues/4241[#4241] — `AbstractDatabaseManager` accepts writes after a failed startup, and is never shut down::
The same `isRunning()` flag is ignored on the write path and honoured on the
shutdown path. A manager whose startup threw keeps receiving events and NPEs on
state it never assigned, once per event, burying the line that named the cause;
and it is never cleaned up, so whatever startup built leaks. Affects JDBC, JPA
and NoSQL alike, on *2.x and 3.x*.

https://github.com/apache/logging-log4j2/issues/4242[#4242] — `log4j-cassandra` leaks the DataStax `Cluster`, so the JVM never exits::
Concrete case of #4241. `cluster.close()` is only reachable from
`shutdownInternal()`, which the failed-startup path skips. The driver's threads
are non-daemon. `LogManager.shutdown()` reports `all resources released: true`
having released nothing.

https://github.com/apache/logging-log4j2/issues/4243[#4243] — `CsvParameterLayout` throws NPE on any event without parameters::
`getParameters()` is null for `SimpleMessage` and goes straight into
`CSVFormat.printRecord`. Only `IOException` is caught, so the NPE escapes: one
error per event, no output, exit code 0. A parameterised call works, so it
survives testing. *2.x and 3.x.*

https://github.com/apache/logging-log4j2/issues/4244[#4244] — `Log4j2EventListener`'s `@ConditionalOnProperty` has no effect::
Registered both as a `@Component` and in `spring.factories`. The latter bypasses
conditions entirely — `SpringApplication` instantiates those directly, with no
bean definition to suppress — so the documented off switch does nothing.

== Not filed

`locateContext` drops the `ServletContext` entry::
Duplicate of
https://github.com/apache/logging-log4j2/issues/2314[#2314], open since February
2024. What this bench adds is the `log4j-appserver` + `log4j-web` trigger and a
captured before/after, which belongs as a comment there.

Interrupting the configuring thread disables every appender::
Reproduced once, but it is a race with no deterministic trigger. Held until it
reproduces on demand rather than filed with a hypothesis attached.
