= Arbiters

One configuration file that resolves differently per environment, without
string-substituting your way through it.

== When they run, and why it matters

An arbiter is evaluated **once, while the configuration is built** — not per
event, and not again afterwards. Three consequences, all of which catch people:

. **The branch not taken is never built.** A typo inside it is never reported,
  because Log4j never constructs those elements. A configuration can be broken
  for production and perfectly quiet in development.
. **Changing the property later changes nothing.** The decision is baked into the
  built configuration; only a reconfiguration re-evaluates it.
. **Two branches may declare the same appender name.** That is the point —
  exactly one survives arbitration, so `AppenderRef` names it unconditionally.

== Not available in every format

The properties configuration format supports **no arbiters at all**. The nearest
spelling fails with `ConfigurationException: No name attribute provided for
Appender`, which names neither arbiters nor the format. XML, JSON and YAML all
support them.

== What the tests assert

* the matching branch is the one that exists — and the file belonging to the
  branch not taken is absent entirely, not merely empty
* `DefaultArbiter` inside `Select` supplies the fallback when nothing matches

== Running it

[source,bash]
----
./mvnw --projects log4j-samples-arbiters test
----
