= Filters

The same filter at different *scopes* — which is what people get wrong far more
often than the filter's own configuration.

== The four scopes

[cols="1,3"]
|===
| Scope | Sees

| Context
| every event in the context, before any logger is consulted

| Logger
| events on that logger, before they reach any appender

| Appender
| only events routed to that appender, from *any* logger

| Appender-ref
| only that one route, leaving the appender open to other loggers
|===

The pair that catches people is the last two. A filter on the *appender* applies
to everyone using it. The same filter on an *appender-ref* applies only to that
logger's route. Moving it between the two changes what other loggers see, and
nothing warns you.

== A naming trap

`LevelRangeFilter` reads backwards. `minLevel` is the *most severe* end,
because Log4j orders levels by decreasing severity — so
`minLevel="ERROR" maxLevel="INFO"` means "ERROR, WARN, INFO", and `TRACE` is
outside it.

== What the tests assert

* an appender-scope `MarkerFilter` admits only marked events
* the same filter inverted on an appender-ref filters that route only
* a logger-scope filter denies before any appender is reached

./mvnw --projects log4j-samples-filters test
