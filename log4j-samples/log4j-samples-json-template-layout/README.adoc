= JSON Template Layout

Structured logging with `JsonTemplateLayout`: a custom event template, the
bundled Elastic Common Schema template, and the resolvers that fill them.

== The failure worth knowing about

An `eventTemplateUri` that does not resolve is *not* a build failure and *not*
an exception. The layout falls back to its built-in template, logs a single line
through the `StatusLogger`, and carries on emitting perfectly valid JSON — in a
shape nobody asked for.

Downstream that surfaces days later as "our index mapping stopped matching".
The only test worth writing is one that reads the field names back, which is what
`JsonTemplateLayoutTest` does.

== What the tests assert

* every field declared in `BenchLayout.json` appears, including a constant
* an MDC key that is not set produces *no field at all*, rather than an empty one
* the exception resolver renders the stack trace when a throwable is present
* the bundled `EcsLayout.json` emits Elastic's names — `@timestamp`,
  `log.level` — rather than Log4j's

== Running it

[source,bash]
----
./mvnw --projects log4j-samples-json-template-layout test
----
